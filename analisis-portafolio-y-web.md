Web contrastada: código local Astro de este proyecto, no una publicación en producción. Se revisaron el texto extraíble y una vista renderizada de las 55 páginas; las páginas basadas en fotografías tienen menos detalle textual. **Las referencias `p. N` son páginas físicas del PDF.**

## Alcance y reglas para usar estos datos

- El PDF presenta a **Plásticos Santuario Sincelejo** y menciona una segunda sede en **Plato, Magdalena**, llamada allí *Plásticos Antioquia* (p. 3). La web local habla de **Caucasia, Antioquia**. Se debe confirmar qué productos, condiciones, historia y afirmaciones corporativas corresponden a Caucasia antes de publicarlos como propios de esa sede.
- Una fotografía prueba que una familia aparece en el portafolio, pero **no prueba inventario actual, precio, marca disponible, capacidad, material, certificación o cobertura de entrega**. Las variantes se registran solo donde el PDF las etiqueta de forma legible.
- `Familia` significa tipo de producto; `variante` significa capacidad, dimensión, color, forma o presentación que el portafolio menciona. Las grafías defectuosas se normalizan para facilitar búsqueda, sin inventar especificaciones.
- Las categorías de la web son **agrupaciones comerciales que se solapan**: una caja de cupcakes pertenece a cajas y repostería; una bolsa biodegradable, a bolsas y biodegradables. Para la experiencia interactiva conviene guardar una categoría principal y etiquetas secundarias.
- **Estado de evidencia:** `texto` = etiqueta legible del PDF; `visual` = identificación de una fotografía; `por confirmar` = lectura, propiedad o vigencia que requiere al negocio. La tabla es un inventario de familias y variantes visibles, no un catálogo de SKU listo para venta.

## 5. Datos listos y pendientes para la sección interactiva

**Modelo mínimo recomendado (aún no implementado):** `id`, `nombre`, `categoriaPrincipal`, `etiquetas`, `familia`, `descripcionCorta`, `variantes[]`, `materialConfirmado?`, `usoSugerido?`, `imagenesAprobadas[]`, `paginasFuente[]`, `estadoValidacion` y `consultable`. Cada variante debería tener `id`, `etiqueta`, `capacidad/medida` con unidad explícita y `referenciaProveedor?`; precio y existencias solo si el negocio aporta una fuente actualizada. Esto enseña a distinguir **datos de catálogo** de **inventario transaccional**: la web puede explorar productos y generar consultas sin simular una tienda.

**Priorización de contenido:**

1. Confirmar con Caucasia qué familias del PDF vende actualmente, cuáles son bajo pedido y cuáles son exclusivas de Sincelejo/Plato. Esta decisión define el alcance real del catálogo.
2. Preparar un registro por producto o familia con foto autorizada, nombre, categoría principal, etiquetas y referencia de proveedor. Para bolsas, cajas, vasos y frascos, pedir la tabla de variantes y unidades exactas.
3. Solicitar fichas técnicas para material, contacto alimentario y afirmaciones «biodegradable», «compostable», «reciclable» o «reutilizable». Separar material de beneficio ambiental.
4. Confirmar identidad de marca/sedes, lemas, historia, dirección, redes, logística, personalización y vigencia de las marcas visibles en el PDF.
5. Implementar la exploración en `/lineas/` en una fase posterior: primero un conjunto curado y validado de familias, filtros útiles, selección de variante y mensaje de WhatsApp con el contexto elegido. Verificar navegación por teclado, móvil y estados sin resultados.

**Errores que evitar:** inventar SKU o medidas desde fotos; inferir que todos los productos bajo el encabezado «biodegradables» cumplen esa propiedad; confundir bolsas PP con biodegradables; copiar la historia de Sincelejo a Caucasia; publicar sabores de coctelería como lista completa cuando el PDF dice que faltan; usar fotografías del PDF en la web sin verificar autorización y calidad de exportación.
